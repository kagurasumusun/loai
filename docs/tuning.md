# 極限チューニング解説

loai が 16GB RAM + Intel iGPU で重いモデルを動かすために講じている対策の技術解説です。

## 1. メモリ収支の全体設計

```
16GB RAM
├─ Windows 11 + 常駐アプリ    約 4.5GB
├─ モデル重み (Q4_K_M)         約 4.7GB  (qwen3-8b)
├─ KVキャッシュ (q8_0, 16k)    約 1.2GB
├─ 計算バッファ等               約 0.35GB
└─ ヘッドルーム                 約 5GB   ← ここが残れば安全
```

`loai doctor` はこの収支を貴方のPCの実測空きRAMで計算し、載る最大のプロファイルを提示します。

## 2. KVキャッシュ量子化 — 最大の削減源

生成中のモデルは直前のトークンの注意スコア (K/V) を保持します。これが実は重量級:

| モデル | fp16 KV @16k | q8_0 | q4_0 |
|---|---|---|---|
| Qwen3-8B (36層, GQA 8頭) | 2.25GB | **1.21GB** | 0.61GB |
| Qwen3-14B (40層) | 2.62GB | 1.31GB | **0.67GB** |
| Qwen2.5-Coder-7B (28層, GQA 4頭) | 0.91GB | **0.49GB** | 0.25GB |

llama.cpp では `--cache-type-k q8_0 --cache-type-v q8_0` で指定しますが、**Flash Attention (`-fa on`) が前提条件**。loai はこの2つをセットで起動します。

## 3. 起動パラメータの自動縮退ラダー

環境によっては一部フラグが使えないことがあります (古いビルド、ドライバ差異、モデル種別)。loai は起動失敗を検出するたびに設定を1段ずつ緩めて再起動します:

1. フル設定 (`-fa on` + KV量子化 + `--jinja` [+ 思考無効kwargs])
2. 思考kwargsを外す
3. 旧式 `-fa` (値なしフラグ) を試す
4. FA と KV量子化を外す (fp16 KV)
5. `-ngl 0` (GPUオフロード全解除)
6. GPUバックエンドならCPUエンジンで 1〜5 を再試行

「どの環境でもとりあえず動く」ことを最優先にした設計です。

## 4. Iris Xe (統合GPU) の正しい扱い

Iris Xe は専用VRAMを持ちません。llama.cpp の Vulkan バックエンドはシステムメモリを共有メモリとしてオフロードします:

- 重みが「載る」こと自体はRAM消費と同義 (総RAM収支は不変)
- 利点は **GPUの行列演算ユニット** を使えること。iGPUでもCPU比 1.5〜2倍程度の高速化が見込める
- ドライバが共有メモリ上限 (通常RAMの半分) を超えるオフロードは失敗する → ラダーが `-ngl 0` に縮退
- **`loai bench`** でVulkanとCPUの実測比較を行い、速い方を推奨 (`--apply` で設定保存)

## 5. スレッド数の調整

Intel Core i7 (第12世代以降) は P コア + E コアのハイブリッド構成です。llama.cpp に論理コア数を渡すと E コアの遅さが全体を引っ張ります。loai は物理コア数を検出し `[2, 8]` にクランプします (`-t` 上書き可能)。

## 6. エージェントの文脈管理 — 16GBの真のボトルネック

モデル自体のRAMより、**エージェントが文脈 (ctx) を食い潰す** 方が先に破綻します。loai の対策:

1. **リポジトリマップ**: 起動時にファイルツリーを圧縮形式で1回だけ注入 (`src/ (12 files, 34KB)`)。全ファイル読み込みを抑制
2. **read_file の行範囲指定**: モデルは必要な行だけを読む (既定300行、上限800行)
3. **ツール出力上限**: 1ツール8,000文字で打ち切り (モデルには打切り明示付き)
4. **決定論的トリミング**: 文脈が予算 (ctx − 2000トークン) を超えたら、古いツール出力から順に `[古いツール出力を省略 (N文字)]` に置換。システム指示と直近4メッセージは絶対保持
5. **トークン推定**: CJK文字 ≒ 1トークン / ASCII 4文字 ≒ 1トークンの軽量推定器で毎ターン監視

これにより実質的な作業窓口を確保しつつ、KVキャッシュ増大 (RAM圧迫) を自動的に頭打ちにします。

## 7. 小型モデルでもツール呼び出しを成立させる二重経路

qwen2.5-coder-1.5b クラスのモデルは、OpenAI形式の `tool_calls` を正しく返せないことがあります。loai は:

1. **正規経路**: llama-server (`--jinja`) によるネイティブツール呼び出しストリーミング
2. **フォールバック経路**: 本文内の `<tool_calljson>` / `<tool_calljson>` / ```` ```json ```` ブロックをパース

を両方実装し、どちらの形式でもエージェントループが継続します。edit_file が一意一致しない場合は「類似行のヒント」をモデルに返し、自己修復を促します。

## 8. さらに詰めたい人へ

- `~/.loai/config.json` で `ctx` / `threads` / `ngl` / `kv_quant` を手動上書きできます
- SYCLバックエンド (Intel GPU最適化・公式ビルドあり `bin-win-sycl-x64.zip`) は `loai install --backend sycl` で導入可。要: Intel GPUドライバ最新版
- レジューム付きダウンロードは `~/.loai/tmp/` の `.part` を利用。手動で再開も可能
- llama-server のログは `~/.loai/logs/llama-server.log` に常に保存され、起動失敗時に自動で末尾12行を表示します
